# Deploy to the NEW GitHub + Render accounts

Quick start for moving this app to a fresh GitHub repo and fresh Render account.

## 1. Push to the new GitHub repo

```bash
# from the project folder
git init
git add .
git commit -m "Dispatch Hub — broker/driver auto-fill + dashboard analytics"
git branch -M main
git remote add origin https://github.com/YOUR-NEW-USERNAME/YOUR-NEW-REPO.git
git push -u origin main
```

`.gitignore` already excludes `node_modules/`, `data/`, and `.env` — do not commit them.

## 2. Create the Render service

1. Sign in to Render with the **new account**: <https://render.com> → **New + → Blueprint**.
2. Connect the new GitHub repo. Render reads `render.yaml` and creates the service.
3. In the new service → **Environment**, set these (the ones marked `sync: false`
   have no value until you set them):

| Env var | What to put |
|---|---|
| `ADMIN_PASSWORD` | strong admin password (used for the `admin` login) |
| `DISPATCHER_PASSWORD` | dispatcher's initial password (must change on first login) |
| `APP_BASE_URL` | `https://dat-one.onrender.com` (shown under Render Settings) |
| `GOOGLE_CLIENT_ID` | from GOOGLE_SETUP.md step 4 |
| `GOOGLE_CLIENT_SECRET` | from GOOGLE_SETUP.md step 4 |
| `GOOGLE_REDIRECT_URI` | `https://dat-one.onrender.com/auth/google/callback` |
| `SESSION_SECRET` | already auto-generated by render.yaml — leave as is |
| `OPENAI_API_KEY` (optional) | free key from console.groq.com (see CONTEXT_PROMPT.md) |
| `OPENAI_BASE_URL` (optional) | `https://api.groq.com/openai/v1` |
| `OPENAI_MODEL` (optional) | `llama-3.1-8b-instant` |
| `DAT_USERNAME/PASSWORD/API_TOKEN` (optional) | real DAT access — see "DAT load board (live)" below |
| `DAT_BASE_URL` (optional) | confirm against your DAT Developer Portal docs (default `https://api.dat.com`) |
| `DAT_LOAD_SEARCH_PATH` (optional) | confirm against portal docs (default `/loadboard/loads/search`) |
| `DAT_METHOD` (optional) | `GET` or `POST` (default GET) |
| `SMTP_HOST` (optional) | for new-user invite emails, see "Invite emails" below |
| `SMTP_PORT` (optional) | `465` (SSL) or `587` (STARTTLS) |
| `SMTP_SECURE` (optional) | `true` for port 465 |
| `SMTP_USER` (optional) | SMTP login (e.g. your Gmail address) |
| `SMTP_PASS` (optional) | SMTP password / Gmail App Password |
| `MAIL_FROM` (optional) | e.g. `"DAT One" <you@gmail.com>` |

4. Trigger a deploy. First deploy installs deps and boots.

### DAT load board (live)

To switch the DAT tab from demo to live data you need a paid DAT REST API account.
Activation (per [TAI Software's DAT guide](https://learn.tai-software.com/knowledge/dat-rest-activation)):
email **techsupportteamleads@dat.com** with your company name, main contact, MC
number, and a dedicated **service-account email** (e.g. `datserviceaccount@yourcompany.com`);
DAT creates the account and sends a password. Then set `DAT_USERNAME` + `DAT_PASSWORD`
(or `DAT_API_TOKEN`) in Render. Confirm `DAT_BASE_URL` / `DAT_LOAD_SEARCH_PATH` against
your developer portal docs (developer.dat.com) and adjust if needed. If the API call
fails, the app logs the error and shows demo data — it never crashes.

## 3. Data persistence (important)

- **Free tier**: Render restarts the service after inactivity — the SQLite DB resets
  (fresh DB each start, including your Google connection). Everything still works;
  you just log in and reconnect Google after a cold start.
- **Keep data forever**: upgrade to Starter (~$7/mo), then in `render.yaml` uncomment
  the `disk:` block and set `DATA_DIR: /var/data`:

```yaml
    disk:
      name: dat-one-data
      mountPath: /var/data
      sizeGB: 1
```

and change the `DATA_DIR` env value to `/var/data`.

## 4. First login

1. Open `https://dat-one.onrender.com`, log in as `admin` / your `ADMIN_PASSWORD`.
2. **Users** page → create your dispatcher accounts (they get their own isolated
   workspaces and must change password on first login).
3. **Settings → Integrations → Connect Google** (follow GOOGLE_SETUP.md).

## 5. Invite emails (when you add a user, they get an email)

When an admin creates a user with an email address, the app automatically emails
them their **username, default password and the app link** (with install-as-app
instructions). Sending order:

1. **SMTP** if configured (recommended — reliable and independent of Google),
2. otherwise the **admin's connected Google** account (Gmail API — works with zero
   extra setup once Google is connected in Settings),
3. otherwise the email is skipped (user creation still succeeds — you'll see a
   warning toast).

### Option A — Gmail App Password (recommended, free)

1. Turn on **2-Step Verification** for the Gmail account: <https://myaccount.google.com/security>
2. Create an App Password: <https://myaccount.google.com/apppasswords> → create one
   for "Mail" → copy the 16-character password (spaces are fine).
3. Set in Render:

| Env var | Value |
|---|---|
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_SECURE` | `true` |
| `SMTP_USER` | your Gmail address |
| `SMTP_PASS` | the 16-char App Password (spaces optional) |
| `MAIL_FROM` | `"DAT One" <your@gmail.com>` |

Other providers work too (Zoho, SendGrid, Outlook…) — just point `SMTP_HOST` /
`SMTP_PORT` / `SMTP_SECURE` at their settings.

### Option B — rely on the admin's connected Google

No env vars needed. The email is sent from the Gmail account that the admin
connected in Settings (requires `GOOGLE_CLIENT_ID/SECRET` + a connected account).
Emails fail if that admin hasn't connected Google.

> The default password travels in the email in plain text — the new user is forced
> to change it on first login, so keep default passwords simple and unique.

## 6. Custom domain (optional)

Render Settings → Custom Domains → add domain, then update **both**:
- Render env: `APP_BASE_URL` + `GOOGLE_REDIRECT_URI`
- Google Cloud: authorized origins + redirect URIs (add the new domain versions;
  keep the old ones until DNS settles).

## 7. Update cycle

```bash
git add . && git commit -m "..." && git push
```

Render auto-deploys on every push. The DB and Google connection persist between
deploys (only a service restart on free tier resets them).
